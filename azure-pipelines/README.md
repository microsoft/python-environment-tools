pre-release.yml: This should build from the `main` branch and publish to the Azure Pipeline feed. This will be consumed by extensions that are also doing pre-release builds. Signing is required on this build.

devdiv-pre-release.yml: DevDiv replacement for the MonacoTools `pre-release.yml` pipeline. It has the same triggers, build matrix, version suffix, and `bin-<target>` artifacts. Like `pre-release.yml`, it only supplies parameters; the logic lives in `templates/rust-package.yml`, a DevDiv copy of `microsoft/vscode-engineering`'s `azure-pipelines/rust-package/pipeline.yml` that extends the MicroBuild 1ES template. Signing uses MicroBuild through `signing/sign.proj`: Windows `pet.exe` is signed with Microsoft400 in its build job, and all macOS `pet` binaries are signed with MacDeveloperHarden and notarized with 8020 in a single job. Linux binaries are not signed.

The DevDiv pipeline runs APIScan on the x64 Windows artifact and uploads results to TSA using `tsaoptions.json`. The `VSEng-APIScanSC` service connection must be authorized for the pipeline. Before disabling Monaco pipeline 591, merge this pipeline to `main`, set DevDiv definition 28980's default branch to `main`, verify a successful seven-target run, and migrate the Python Environments extension's pre-release consumer to the DevDiv artifacts.

stable.yml: This builds tags matching `release/<year>.<build>`, where `<year>` is four digits and `<build>` is numeric, and publishes to the Azure Pipeline feed. The pipeline is triggered when a matching tag is pushed to GitHub. This will be consumed by extensions when publishing stable builds. Signing is required on this build.

playground.yml: This pipeline is for engineering/testing purposes so we can do fixes and tests without affecting the pipeline feeds. This will not publish to the Azure Pipeline feed. Signing is not required on this build.
